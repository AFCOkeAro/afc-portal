E1 · design notes

  • Drill-down is not teal (S-4). The registered counts are --afc-bg-action, underlined, with a chevron-right glyph. The v3 wireframe convention says “teal, underlined” — that convention is retired; see the divergence note on this issue.
  • Capacity is shown, never decided. The progress bar and the waitlist count read straight from the server response. A bar that turns neutral at 100% is the only change the UI makes, because “full” is a different state, not a different number.
  • “Registration off” is a badge, not a blank cell. Jakob's Law: a missing value must not read as a bug. Same for the outreach row, where registrations do not exist at all — it says so in words.
  • Walk-up counts are not drillable. The row shows a lock glyph and the words “no registration”. Offering a drill-down into nothing would be a false affordance (Norman: false signifier).
  • View switch is a segmented control with aria-pressed, not a tablist, because the table below never swaps panels.
  • Deferred features are three visible cards, not omissions. Working memory (Miller) would make three competing warnings a wall; they sit at the foot of the list, below the task, so they inform without competing.

E2 · design notes

  • The programme is the page, not a tab. The board chose sessions, tracks and speakers over the earlier flat schedule. Three track columns let a person compare options in one horizontal glance — Chunking: three groups beat ten loose rows, and Serial Position says the first item in a track is read first, so the opening session sits at the top of column A.
  • Per-session capacity is on every session card, because two sessions can be full while the event has 388 places left. A single event-level number would be a lie. Full sessions use the neutral fill, not the warning amber — a full room is a fact, not a fault.
  • “Full — no walk-in” is a badge with a glyph, so it survives greyscale and colour blindness. Colour-independence is not optional for a door screen that is read in sunlight.
  • The strip is anchor navigation, not a tablist. It is a nav of links; the active item carries aria-current; the content scrolls and never unmounts. There is no role="tablist" anywhere in this file.
  • Two capacity failure modes, both designed: the whole event can be full (Teenage Camp, E5) or a single session can be full (Track B). The UI shows the server's answer and offers the waitlist — Postel's Law: the server is the authority, the client does not decide.
  • Medical fields are absent on purpose, and the page says so out loud. Absence that reads as a decision nobody made is exactly the failure the brief warns about, so the absence is stated with its reason.
  • Three “Later” panels sit where the feature would live: inside Track C for streaming, under the programme for networking, and beside the venue for sponsors. Each names what is missing and what it would need.

E3 · design notes

  • The form is one column per field inside a two-column page. Single-column forms beat two-column forms on error rate, and this form is long. The right rail is a summary, not a field column.
  • The programme sub-form is the screen's real content. It is the reason this page exists after the board's decision on sessions, tracks and speakers, so it gets the widest column and a summary table beneath it.
  • “Session capacity — blank inherits the event cap” is stated, because a blank field is otherwise ambiguous between “unlimited” and “same as above”. Ambiguity is where portals fail quietly.
  • The age/consent mismatch is a first-class blocked panel, not a footnote. The server refuses the publish; the UI states why in words and links to the fix. Consent is a hard gate with no override path, and the design makes that visible instead of enforcing it invisibly.
  • “Full” sessions get an amber warning at edit time, because changing capacity below the taken count is the destructive-adjacent action here. The message says the server will refuse rather than overbook.
  • No hybrid field exists, on purpose. An input on screen reads as a decision. The dashed panel says the feature is undecided and lists what it would need.
  • Cancel is a badge-red button in a “Danger zone” whose copy says what is kept. It confirms, and the confirm names the 812 affected people — that is not confirmshaming, that is informed consent by a branch admin.

E4 · design notes

  • Mobile 390 by declaration. This page is opened from a WhatsApp link on a phone, on data, at a bus stop. That is the only viewport that matters; the desktop layout is the same content centred.
  • Plain language, Inverted Pyramid. What, when, where, cost, who — in that order, above the fold. The programme is deliberately below the capacity block: most people register for the event, not for a session, and the sessions are the long part.
  • “What we ask, and why” is on the public page, not in a policy PDF. It names the three fields we take and the five we do not. Data minimisation is only credible when it is stated where the person decides whether to give it.
  • The under-18 rule is stated before the register button, not discovered in the form. Progressive Disclosure cuts both ways: a surprise guardian requirement at the last field is a drop-off, not a safety win.
  • Full sessions are visible on the public page. Hiding them would let someone register for the event and arrive to a locked door. The copy says the waitlist is available after registering — the honest route, not a fake close.
  • No map embed, no chat, no video. The first is a third-party dependency we do not need for a street address; the other two are undecided or rejected, and both are marked on screen.

E5 · design notes

  • Guardian consent before a minor is registered is a gate, not a warning. 5B leads with a .afc-blocked panel naming the policy, then collects guardian name, phone and two explicit ticks. There is no path that registers a minor without it.
  • The guardian is the messaging recipient, stated twice: in the phone-field help, and as a .afc-badge--gold “Consent holder” on the fieldset. Gold is used here as a graphic rule only — never as text or a fill behind white.
  • The minor's fields are minimal on purpose, and the form says which fields it is not asking for — phone, email, photo. An explicit “we are not asking” is stronger than silence.
  • Withdrawn reads as settled (S-3). 5C uses the neutral ramp alias --afc-status-withdrawn with a circle-slash glyph and the word “Withdrawn”. There is deliberately no retry control anywhere near it, and the copy says we do not chase the guardian to reverse it. A withdrawn opt-out that sits next to a “Try again” button is a nudging mechanism.
  • Colour never carries the state alone. Withdrawn is neutral grey — deliberately the same hue family as ordinary neutral status. What distinguishes it is the glyph, the word and the absence of a next step. That is colour-independence working as intended, not a failure of contrast.
  • A safeguarding hold is rose (danger) and says what it will not say. It does not reveal who placed the hold or why, names the role that can lift it, and gives a reference code. It also does not dead-end the visit: an adult can still attend and be checked in at the door.
  • Validation names the fix and never blocks submission to report a problem — colour + glyph + 3px rule + “enter the full 11-digit number”. Getting “Invalid” in a safeguarding form costs trust at exactly the wrong moment.
  • Waitlist is described honestly. Position 12 of 38, a 12-hour hold window, and the sentence “not a promise”. Overstating a waitlist would be a bait-and-switch at the moment of hope — the opposite of what this church should do with a teenager's Saturday.

E6 · design notes

  • Two paths, one weight. The scan/search switch is an equal-width segmented control with the same icons at the same size. Nothing about the layout says “real” and “fallback”. That was the board's explicit instruction and it is a real design constraint, not a copy line.
  • Both paths write the same record with a different method value — ticket-code or door-name. The report distinguishes them for analysis and neither is treated as second-class. Postel's Law: the same record, a tolerant reader.
  • Idempotency is stated in the UI, because an usher needs to trust the phone: “we have not written a second attendance row”. A duplicate is amber and informative, not a red error. Red would train people to tap harder.
  • Per-session capacity is on the door screen, with the admit-until time. A room's capacity is what an usher is actually enforcing at 10:20, not the event's 1,200.
  • Undo exists for 60 seconds only. Forgiveness: an usher who checked in the wrong person should be able to fix it while the person is still standing there. After 60 seconds it is a record.
  • The consent state on this screen uses the S-3 rules. “4 messages declined” is the withdrawn alias plus a struck-through count — a settled fact, not a red failure to fix.
  • Offline is a first-class state with a stated staleness, because a door that stops working at 09:00 is the failure a church cannot absorb. It keeps admitting on a printed roster and tells the usher how far behind it is.
  • A walk-up is a legitimate category, labelled as itself, not squeezed into “registered”. That is what makes the name search a first-class path rather than an exception form.

E9 · design notes

  • Every count is a control, not a label. S-4: --afc-bg-action, underlined, with a drill-down glyph. There is no teal on this screen and none anywhere in this file — teal #0184B1 is Youth Development's sampled accent, and using it for every drill-down would brand general navigation as one department.
  • Comparison is present but secondary. “+18% vs 2025” sits under the number in neutral grey. Von Restorff says one highlighted figure gets remembered; five of them become wallpaper.
  • The funnel names the biggest drop and refuses to excuse it. 1,946 opened, 1,214 submitted, and the likely cause is stated — the guardian branch. The report then says explicitly that this is not a reason to weaken it. A dashboard that quietly optimises away a safeguarding requirement is the failure mode worth designing against.
  • “Fill” is checked-in ÷ server-enforced per-session capacity, never ÷ event capacity, and the footnote says so. The 1,200 in the Main Hall and the 40 in the Chapel Annex are not comparable without that.
  • The consent coverage panel is the S-3 state matrix in production form: captured (green), not captured (amber + the reason “excluded from SMS”), withdrawn (neutral alias, struck-through count, no retry), safeguarding escalation (rose, and nothing else). The three are never merged into one number.
  • Restricted sections are not rendered. The branch-leader variant shows one row and no greyed-out ghosts. Jacob's Law extends to permissions: the affordance a person cannot use is a lie about what they can do.
  • Partial failure is designed. Two sources down renders two zeros nowhere — it renders the two that worked and says the other two are missing, not zero. This is the same rule as formula_pending never being drawn as “—”.
  • Two commercial metrics are deliberately absent and marked: online attendance (undecided) and sponsor ROI (no model, and putting a commercial frame on ministry attendance is not a call this product should make).

E10 · design notes

  • The calendar is where a clash becomes visible. The 14–15 November collision between the Summit and Thanksgiving overflow is the reason this screen exists as its own surface, and the timeline panel names what happened and when it was resolved. A report cannot show a clash; it can only show a low number afterwards.
  • Five categories, each with a glyph and a word. The legend is swatch + icon + label, so it survives greyscale and colour blindness. Colour never identifies a category — the same rule the design system applies to department seals.
  • Capacity travels onto the calendar chip (“388 seats left”, “Full · 38 waitlisted”) so a clash is visible with its consequence attached, not as a neutral square.
  • Mobile gets an agenda list, not a shrunken grid, and the screen says why: seven columns at 390px is about 48px per column, below the 44px target once padding is removed. That is a content-driven breakpoint, consistent with the design system's own 48rem table→card rule.
  • The legend has five entries, not six. There is no “streamed” swatch, because the hybrid decision does not exist. A swatch with nothing behind it is an intent nobody made. The dashed panel says where it would go.
  • Load failure is a loud empty, not an empty month. The copy is explicit: “nothing here is empty — it simply did not arrive”. This is the single most important state on E10 for the reason in the brief.
